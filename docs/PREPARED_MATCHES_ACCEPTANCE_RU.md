# Игровая проверка подготовленных матчей

Это checklist, не результат прогона. Нужны два тестовых аккаунта, обновлённый core,
одинаковая MSS и `DisplayErrors=1` в `[Disciple]` действующего `Disciple.ini`.
Используйте нерейтинговую подготовку; не изменяйте реальные турнирные результаты.
После изменения локальных Lua перезапустите клиент. Для разных наборов файлов нужны
раздельные тестовые установки, а не замена файлов работающего хоста.

| Проверка | Ожидаемый результат |
| --- | --- |
| Создание | Только назначенный хост получает Yes/No; до согласия нет генерации/комнаты. Рейтинг, участники и условия верны. Обычный короткий матч — одно окно, длинные ники/условия читаются полностью. |
| Отказ и повтор | «Нет» не повторяет тот же popup; новая попытка снова предлагается. |
| Занятый клиент | Во время другой игры, перехода, помощи или пароля окна нет; в свободном лобби появляется. |
| Retry/Cancel | Retry создаёт новое содержимое при прежних расах/spins; Cancel возвращает в лобби. Следующая попытка работает. |
| Отмена сайта | Отмена генерации/preview блокирует старый Accept. Cancel одновременно с CreateRoom не создаёт дубль; поздняя отмена сохраняет созданную комнату и согласованного лорда. |
| Настройки хоста | После Accept совпадают race/lord и корректен портрет; хост назначен независимо от организатора. Гость выбирает свои параметры вручную. |
| Выбор Lua | Выбирается старшая числовая версия нужного семейства, не самый новый mtime; Duo/Trinity/forks не смешиваются. Отличный от примера MD5 разрешён. |
| Ошибки Lua | Нет семейства, одинаковые старшие версии, недопустимый spin/размер/число игроков — понятная ошибка после «Да», без комнаты и без автоматического выбора старого Lua. |
| Вход гостя | Окно только после созданной комнаты; работает для уже онлайн, нового login и возврата из игры. После «Да» гость действительно появляется в комнате. |
| Изменение комнаты | Исчезнувшая/полная комната отказывает; другая не выбирается. Ручной Join и приглашение одинаково проверяют FilesHash/TemplateHash/пароль. |
| Отзыв приглашения | Отзыв закрывает только его окно; поздний ответ не входит. Уже начатый вход не разрывается. Отказ помнится при повторном login в том же процессе. |
| Профиль и reconnect | Отключённые приглашения и чужой recipient не показывают окно. Старый callback после переподключения не действует. |
| `111` | После начала игры оба клиента перезапускают принятую карту; Retry снова исполняет Lua, сохраняются расы/спины/лорды/портреты. Победа не начисляется. |
| Save/resume | Upload удаляет точный локальный сейв только после server ACK; LocalOnly/ошибка сохраняют файл. Загрузка хода джойнера не повторяет доход и не блокирует ввод хоста на следующем ходу. |
| Онлайн-хеш | После login общий FilesHash появляется без создания комнаты; после logout текущая online-проекция его не показывает. На медленном диске login не ждёт worker. |

Пока остаётся отдельное ограничение: Setup имеет общий deadline 15 секунд, включая
ожидание модалки. Долгое перекрытие UI может не дать выставить обязательного лорда;
этот случай нельзя считать пройденным по одному успешному обычному запуску.

При первом native error, неверном выборе, зависшем возврате или второй комнате
остановите прогон. Сохраните время, preparation/attempt ID, локальный Lua filename/MD5
и соответствующий участок журнала. Ошибки не скрывать через `DisplayErrors=0`.
Native createServer failure не следует провоцировать порчей файлов.
