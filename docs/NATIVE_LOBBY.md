# Native-часть лобби

Адреса ниже относятся только к Russobit x86, `Discipl2.exe` размером 4 187 648 байт,
SHA-256 `1375cdef09ec470ee64fe5693fb734d7c69fb215212311d997f792b258a642eb`.
Это статические основания реализации, а не отметка игровой приёмки других EXE.

## Зачем нужны hooks

| Участок | Native-наблюдение | Изменение MSS |
| --- | --- | --- |
| Сохранение | SendSaveGameMsg `0x40639b` принимает this в ECX и заканчивается `retn 8`; GameSaved ctor `0x4786aa`, vtable `0x6d4b44`, success/path по +0x10/+0x14 | Штатный save хоста; копия пути до обработки очередью; Upload ждёт подтверждения долговечного хранения перед удалением точного открытого файла. |
| Возобновление | Load переводит игроков в AI (`0x422D3D`); StartScenario джойнера разрешается после хоста (`0x42BC1A`). Initial BeginTurn отправляется ещё до его активации. | Восстановление очереди по сохранённому активному игроку, не повторный старт дня. |
| Ввод хоста после load | CStratInterf ctor `0x48D02C` берёт input lock, оставляя waitMode=0. Чужой AI BeginTurn `0x491637` добавляет второй lock; свой TurnInfo `0x4917B4` снимает только один. | Перед Strat Notify1 существующий ObjectLock Notify1 выставляет Full для уже заблокированного UI. Счётчики не меняются. RTTI и адресат проверяются до обращения к offsets. |
| Раса хоста | Fresh CMenuLobby ctor `0x4e250e`: `0x5735a2` возвращает список рас; `0x55ef42` берёт первый узел; `0x47ce79` создаёт ReqRace. | Согласованная раса первая только в native setup; набор рас генератора не подменяется после getContents. |
| Лорд/портрет | BTN_LORD callback `0x4e35de` меняет категорию, но сохраняет текущий face из LobbyData+0x20; отправляет ReqLord и обновляет UI. | Вызов штатного enabled callback и проверка AnsStartInfo вместо записи private полей. |

У resume UI CInterface-подобъект смещён на +4; относительно него counters
расположены по +F0/+F4, waitMode по +F8. Проверенные RTTI: CStratInterf и CPhaseGame.
Порядок ObjectLock::Notify1 перед Strat::Notify1 задан native таблицей `0x416F2A`.
Без этих условий менять waitMode нельзя. LAN и одиночная игра не затрагиваются.

`nativeSaveSupported` проверяет EXE и читаемый пролог, поскольку обычное определение
версии MSS основано только на размере файла. После начала разрешённого transfer
повторная проверка того же API не нужна. Сетевые размеры/ID, stale callback/token,
RTTI перед cast и порядок очередей при `111` остаются обязательными.

## Небольшие общие исправления

- Пустой `MOD_POTION` означает invalidId без native исключения; неправильный
  непустой ID по-прежнему читается строго. Это устраняет диагностическое окно при load.
- Отсутствующий `Scripts/turn.lua` пропускается после штатного begin-turn.
  Ошибки существующего файла обрабатывает protected loader stable.
- Неудачный setupHook прерывает открытую Detours transaction.

Эти исправления не зависят от ОХ. Подмена DLL, Lua модов и запуск игры не входят
в саму компиляцию. Проверочные шаги: [игровая приёмка](PREPARED_MATCHES_ACCEPTANCE_RU.md).
